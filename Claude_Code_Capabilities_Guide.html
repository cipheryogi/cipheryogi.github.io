Claude Code Capabilities

What Claude Code can do and how to steer it: built-in tools, subagents, agent teams, dynamic workflows, skills, plugins, hooks, permission modes, models, and headless and CI automation.

Built-in tools Subagents · teams · workflows Skills · plugins · hooks Permission modes Headless + CI

Companion guide: Claude Code File Structure & Configuration (where CLAUDE.md, settings, memory, MCP configuration and credentials live).

1. The Mental Model

Four layers: what Claude can do, who does the work, how you extend it, and what keeps it safe.

ToolsBuilt-in actions such as reading and editing files, running shell commands, fetching web pages and asking you questions. MCP servers add more.
AgentsThe main session can delegate to subagents, coordinate an agent team, or run a dynamic workflow that orchestrates many agents.
ExtensionsSkills add reusable instructions, hooks add deterministic automation, and plugins package skills, agents, hooks and MCP servers together.
ControlsPermission modes and rules decide what runs without asking. The sandbox adds OS-level isolation, and checkpoints let you rewind edits.

4. Subagents

A subagent runs in its own context window and returns only its result, keeping the main conversation lean.

How subagents run

Background by default

Subagents start in the background and their result is delivered when they finish. Ctrl+B backgrounds a running task. /tasks shows status and transcripts.

Fork mode

On by default (v2.1.302). In interactive sessions Claude can't wait on a subagent. Set CLAUDE_CODE_FORK_SUBAGENT=0 and restart to let it wait.

Resume

Claude continues an earlier subagent with SendMessage, using its ID or name, and keeps its full history. Explore and Plan can't be resumed.

Forks

A fork inherits the whole conversation and shares its prompt cache, so it is cheaper than a fresh subagent with the same context. Start one with /subtask <task>.

Limits

Nesting up to three layers below the main conversation (CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH). At most 20 running at once (CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS).

Never available to subagents

AskUserQuestion, EnterPlanMode, ScheduleWakeup, Workflow and a few others. ExitPlanMode only when permissionMode is plan.

Custom subagents

A subagent is a Markdown file with YAML frontmatter, and its body is the system prompt. If several definitions share a name, the higher location wins: managed settings, then the --agents CLI flag, then .claude/agents/ (project), then ~/.claude/agents/ (user), then plugins. For subagents, the project copy beats the user copy, which is the opposite of skills.

Save it as .claude/agents/code-reviewer.md, or pass a JSON definition for one session with claude --agents '{...}'. Keep descriptions short: past 15,000 tokens of combined custom descriptions, Claude Code shows a startup warning.

5. Agent Teams (Experimental)

Several full Claude Code instances that share a task list and message each other directly.

Off by default. Enable with CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 in your shell or a settings env block. Teams need an interactive session: claude -p and Agent SDK runs don't spawn teammates.
1

How a team forms

  • Ask in plain language, for example "spawn three teammates to review this PR from security, performance and test angles"
  • Claude launches a teammate when it calls Agent with a name
  • There is one team per session, named session- plus 8 characters of the session ID
  • A teammate can be spawned from a custom subagent definition
2

How it coordinates

  • A shared task list (pending, in progress, completed) with dependencies. Teammates claim unblocked tasks.
  • Direct messages by name. No broadcast: one message per recipient.
  • Teammates load CLAUDE.md, MCP and skills, but not the lead's conversation
  • Teammate permission prompts appear in the lead session
3

Limits and cost

  • /resume and /rewind don't restore in-process teammates. No nested teams.
  • Shut a teammate down by asking the lead. The team config directory is removed when the session ends. The task list stays until the cleanupPeriodDays sweep.
  • Roughly 7x the tokens of a standard session when teammates plan. The docs suggest 3 to 5 teammates.
  • Display: in-process (default) or split panes with tmux or iTerm2 (teammateMode)

Quality-gate hooks: TeammateIdle, TaskCreated and TaskCompleted. Exit code 2 keeps a teammate working, or blocks creating or completing the task.

6. Dynamic Workflows

A JavaScript script that Claude writes and a runtime executes in the background, orchestrating dozens to hundreds of agents.

Subagents

A few focused tasks whose results come back to the main conversation.

Agent teams

A handful of long-running peers that need to talk to each other.

Dynamic workflows

More agents than one conversation can coordinate, or orchestration you want codified and rerunnable: codebase-wide audits, large migrations, cross-checked research, fix-until-green loops.

  • Start one by typing ultracode in a prompt or asking Claude to "use a workflow". /effort ultracode lets Claude plan workflows for every substantive task. /workflows shows runs, and s saves a run's script.
  • Saved workflows live in .claude/workflows/ or ~/.claude/workflows/ and run as /<name>. /deep-research is bundled.
  • Script API: agent(), pipeline(), parallel(), phase(), log() and args. Intermediate results stay in script variables, so Claude's context holds only the final answer.
  • Limits: 16 concurrent agents by default, 1,000 agents per run, no user input mid-run, no direct filesystem access from the script. Disable with "disableWorkflows": true.
export const meta = { name: 'audit-routes', description: 'Audit every route handler for missing auth checks' }

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
})
const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }))
return audits.filter(Boolean)

7. Skills and Slash Commands

A skill is a SKILL.md file of instructions. Only its description sits in context until it is used.

Invocation

You run it with /skill-name, and Claude also loads it automatically when the description matches the task. disable-model-invocation: true makes it manual-only. user-invocable: false hides it from the / menu.

Locations

Personal ~/.claude/skills/<name>/SKILL.md, project .claude/skills/<name>/SKILL.md, managed directory, and plugins (/plugin:skill). On a name clash: enterprise, then personal, then project.

Commands merged into skills

.claude/commands/deploy.md and .claude/skills/deploy/SKILL.md both create /deploy. A skill beats a command file with the same name.

Useful frontmatterEffect
description · when_to_useHow Claude decides to apply it. The listing truncates at 1,536 characters, so put the key use case first.
allowed-tools · disallowed-toolsTools usable without prompts during the invoking turn, and tools removed while the skill is active
context: fork · agentRun the skill in a forked subagent (default general-purpose)
model · effort · paths · hooksPer-turn model and effort, file globs that limit auto-activation, and hooks registered on invoke

Inside the body: $ARGUMENTS, $0, $1 and so on for arguments, and !`command` to inject shell output. Keep SKILL.md under 500 lines and move detail into supporting files.

---
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed or wants a commit message.
---

## Current changes
!`git diff HEAD`

## Instructions
Summarize the changes above in two or three bullet points, then list any risks.

8. Plugins and MCP Servers

Plugins package extensions for one-command install. MCP servers connect Claude to external tools and data.

1

Plugins

  • A directory of skills, agents, hooks, MCP and LSP servers, output styles, workflows or monitors. The .claude-plugin/plugin.json manifest is optional.
  • Installed from a marketplace. Anthropic's claude-plugins-official is added on first interactive start.
  • An enabled plugin is part of every session and runs with your privileges
2

Install scopes

  • User (~/.claude/settings.json, the CLI default), project (.claude/settings.json, committed) or local (.claude/settings.local.json)
  • Local beats project, and project beats user
  • /reload-plugins applies changes to a running session
3

MCP servers

  • Add with claude mcp add and manage connections and OAuth in /mcp
  • Tool definitions are deferred by default and loaded on demand through ToolSearch
  • Verify you trust each server: servers that fetch external content can expose you to prompt injection
# In a session
/plugin marketplace add your-org/plugins#v1.2.0
/plugin install commit-commands@claude-plugins-official

# From your shell
claude plugin install formatter@your-org --scope project
claude --plugin-dir ./my-plugin      # load a local plugin for one session

# Remote MCP server (GitHub's hosted server, authenticated with a personal access token)
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer ${GITHUB_PAT}"

MCP scopes, .mcp.json and how to pass server credentials safely are covered in the File Structure & Configuration guide.

9. Hooks

Deterministic automation: Claude Code runs the hook itself, so it happens every time whatever the model decides.

Event groupEvents
SessionSessionStart, Setup, SessionEnd

Worktrees, compaction, modelsWorktreeCreate, WorktreeRemove, PreCompact, PostCompact, PreModelSwitch, PostModelSwitch
OtherNotification, MessageDisplay, Elicitation, ElicitationResult
Five handler types

command (shell, JSON on stdin), http (POST to a URL), mcp_tool, prompt (single-turn model check) and agent (experimental subagent).

Exit codes

0 means success. 2 blocks the action on events that can block, and stderr is fed back. Any other code is a non-blocking error, so exit 1 does not block.

Matchers

Edit|Write is an exact list. Other characters make it a regex, so Edit.* also matches NotebookEdit. The if field takes a rule such as Bash(git commit *).

Block edits to protected files (PreToolUse with exit 2). .claude/hooks/protect-files.sh:

#!/bin/bash
FILE_PATH=$(jq -r '.tool_input.file_path // empty')
for pattern in ".env" "package-lock.json" ".git/"; do
  if [[ "$FILE_PATH" == *"$pattern"* ]]; then
    echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2
    exit 2
  fi
done
exit 0
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh" } ] }
    ]
  }
}
No "pre-commit" hook event exists. To format files Claude edits, use PostToolUse with an Edit|Write matcher. To gate commits Claude makes, use PreToolUse on Bash with "if": "Bash(git commit *)". Where hooks are stored is covered in the File Structure guide.

10. Permission Modes and Rules

The mode sets the default behaviour. Rules carve out exceptions, and deny always wins.

ModeBehaviourUse it for
autoEverything runs, with a separate classifier model reviewing actions. Read-only actions and in-directory edits skip the classifier. Broad allow rules such as Bash(*) are dropped while it is on.Built-in starting mode for interactive terminal and VS Code sessions since v2.1.283
default (Manual)Only reads run without asking. Alias manual.Careful, supervised work. Also the start mode for claude -p (v2.1.302+).
acceptEditsFile edits plus mkdir, touch, rm, rmdir, mv, cp and sed inside the working directoriesFast iteration you review afterwards
planRead-only exploration. Edits stay blocked until you approve the plan.Aligning on an approach first
dontAskDenies everything that would prompt. Actions needing no approval (reads, the read-only command set) and allow-rule matches still run. AskUserQuestion is denied even if allowed. Never in the Shift+Tab cycle.Locked-down CI
bypassPermissionsSkips prompts, but deny rules, explicit ask rules and critical-path rm checks still apply. Refused as root outside a recognized sandbox.Isolated containers and VMs only

Switching: Shift+Tab cycles modes in the CLI. Use --permission-mode <mode> at launch or permissions.defaultMode in settings. auto and bypassPermissions don't take effect from project or local settings, so set them in ~/.claude/settings.json. Admins can turn modes off with permissions.disableAutoMode and permissions.disableBypassPermissionsMode.

Permission rules

RuleMatches
Bash(git log *) vs Bash(git *)Only git log versus all git. The space matters: Bash(ls *) doesn't match lsof, but Bash(ls*) does.
Read(./.env) · Edit(src/**)Gitignore-style paths. //path is absolute, ~/path is home, /path anchors at the settings source (the project's working directory for project settings, ~/.claude/ for user settings). A Read deny also blocks Edit and Write.
WebFetch(domain:example.com)That host only. domain:*.example.com covers subdomains but not the apex.
mcp__github · mcp__github__create_issueAll of a server's tools, or one tool
Agent(Explore)A subagent type
  • Order: deny, then ask, then allow. The first match decides, and specificity doesn't change the order. A bare tool name in deny removes the tool from Claude's context.
  • Compound commands are split on &&, ||, ;, | and newlines, and every part must be allowed.
  • Bash rules are not a security boundary: Bash(rm *) doesn't stop /bin/rm or bash -c. Use the sandbox or a PreToolUse hook for real enforcement.
  • Writes to protected paths such as .git, .claude, .vscode, .mcp.json and shell rc files are never auto-approved outside bypassPermissions. Manual and acceptEdits prompt, auto sends them to the classifier, and dontAsk denies them.
{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git commit *)"],
    "deny":  ["Bash(git push *)", "Read(./.env)", "Read(./secrets/**)"]
  }
}

11. Sandboxing and Checkpoints

An OS-level boundary for shell commands, and an undo history for Claude's file edits.

1

Sandbox

  • Wraps Bash, PowerShell and Monitor commands and their child processes. Off by default. Enable with /sandbox or "sandbox": {"enabled": true}.
  • macOS uses Seatbelt. Linux and WSL2 need bubblewrap and socat. Native Windows is unsandboxed.
  • Writes are limited to the working directory and temp. Network goes through a proxy whose allowlist starts empty.
2

Sandbox caveats

  • Reads cover most of the machine, including ~/.ssh and ~/.aws/credentials, so protect those explicitly
  • Read, Edit, web tools, MCP servers and hooks run outside the sandbox and are governed by permission rules
  • allowUnsandboxedCommands: false removes the escape hatch
3

Checkpoints

  • Every prompt creates a checkpoint of Claude's file-tool edits. /rewind or Esc twice restores code, conversation or both.
  • Files changed only by Bash aren't tracked, and subagent edits usually aren't restored
  • Kept about 30 days. Not a replacement for Git.
{
  "sandbox": {
    "enabled": true,
    "filesystem": { "allowWrite": ["~/.kube", "/tmp/build"] },
    "network": { "allowedDomains": ["github.com", "*.npmjs.org"] }
  }
}

12. Models, Effort and Context

Pick the model by task difficulty, tune effort, and manage the context window deliberately.

AliasResolves to (Anthropic API)Use for
fable · bestFable 5.1 (claude-fable-5-1). best means Fable where available, otherwise Opus.The hardest and longest-running tasks
opusOpus 5.5 (claude-opus-5-5). Default model for Pro, Max, Team, Enterprise and the API.Complex reasoning, architecture, multi-file refactors
sonnetSonnet 5.5 (claude-sonnet-5-5)Daily coding

  • Switch with /model, --model or the model setting. Admins restrict choices with availableModels. Current models run a 1M-token window natively, so the [1m] suffix matters only for Opus 4.6 and Sonnet 4.6.
  • Effort is low, medium, high, xhigh or max, set with /effort. The 5.5 models default to medium.
  • Subagent cost: set model: haiku in a simple subagent's frontmatter, or CLAUDE_CODE_SUBAGENT_MODEL as the default for subagents that don't set their own (add CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 to force it on all).
  • Context: auto-compaction runs near the window limit. Use /context to see what fills it, /compact Focus on ... to summarize with intent, and /clear between unrelated tasks, which costs nothing.
  • Cost reference: the docs report an enterprise average of about $13 per developer per active day ($150 to $250 per month). /usage shows session cost.

Run Claude Code without a person at the keyboard: scripts, pipelines, GitHub, schedules and parallel worktrees.

  --allowedTools "Read" --max-turns 3 \
  --output-format json \

Untrusted repos in -p mode: without --bare, a -p run executes the project's settings hooks and connects its .mcp.json servers with no trust dialog or approval prompt.

GitHub Actions and GitLab

  • /install-github-app installs the Claude GitHub App, stores ANTHROPIC_API_KEY or CLAUDE_CODE_OAUTH_TOKEN as a repo secret, pushes a branch with the workflow file, and opens a ready-to-create pull request in your browser. It works only with github.com repositories and needs admin access.
  • anthropics/claude-code-action@v1 answers @claude mentions when there is no prompt input, and runs in automation mode on any event (including schedule) when prompt is set. Pass CLI flags through claude_args.
  • GitLab CI/CD support is in beta and maintained by GitLab. A job runs claude -p with ANTHROPIC_API_KEY as a masked variable.
name: Claude Code
on:
  issue_comment: { types: [created] }
  pull_request_review_comment: { types: [created] }

    permissions: { contents: write, pull-requests: write, issues: write, id-token: write, actions: read }

      - uses: anthropics/claude-code-action@v1

          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

14. Security and Monitoring

Safeguards built into Claude Code, plus the practices that close the remaining gaps.

PracticeHow
Never commit secretsReference variables instead of literals, and deny reads of secret files with Read(./.env) rules. The File Structure guide shows the full pattern.
Choose the permission mode deliberatelyInteractive sessions start in auto. For Manual, set permissions.defaultMode: "default". Reserve bypassPermissions for isolated containers.
Use real boundaries for real riskEnable the sandbox and use PreToolUse hooks. Bash permission rules and CLAUDE.md text are not security controls.
Trust MCP servers explicitlyApprove .mcp.json servers deliberately. For production data, use least-privilege, read-only credentials (a recommended practice, not a platform rule).
Review before you pushAsk Claude to show the diff before any push, and keep git push behind an ask or deny rule if you want a hard stop.
Audit beyond GitGit doesn't capture what Bash changed outside the repo. Use OpenTelemetry and ConfigChange hooks for audit trails.
Built-in safeguards

Workspace trust dialog, separate .mcp.json approval, curl and wget not auto-approved, command-injection detection, fail-closed matching, and credentials in the Keychain or a 0600 file.

OpenTelemetry

Enable with CLAUDE_CODE_ENABLE_TELEMETRY=1 plus OTEL_METRICS_EXPORTER and OTEL_LOGS_EXPORTER. Metrics include session count, cost, tokens and lines of code.

Privacy defaults

Prompts, responses and tool details are not logged unless enabled. OTel variables in a repo's settings are ignored, so admins deploy telemetry through managed settings.

Prompt patterns and session habits that keep results accurate on large codebases.

17. Quick Decision Guide

When you want something done, start here.

Understand code

"How does the auth flow work?"

Just ask. Claude reads and searches directly. For a broad sweep, ask it to use Explore subagents in parallel.

Delegate

"Refactor all API routes to the new middleware."

A general-purpose or custom subagent through the Agent tool. For hundreds of files, a dynamic workflow.

Collaborate

"I want several agents to debate competing hypotheses."

An agent team. Enable CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1, then ask Claude to spawn teammates.

Repeat a procedure

"We run the same release checklist every week."

Write a skill in .claude/skills/release/SKILL.md and run it with /release.

Always happen

"Every edited file must be formatted."

A PostToolUse hook on Edit|Write.

Never happen

"Claude must never push or read .env."

Deny rules: Bash(git push *) and Read(./.env). Add the sandbox for OS-level protection.

Track progress

"Show me a checklist as you work."

The Task tools (TaskCreate and the rest). On newer models, enable them with CLAUDE_CODE_ENABLE_TODO_TOOLS=1.

Automate

"Review every PR automatically."

anthropics/claude-code-action@v1 via /install-github-app, or a /schedule cloud task.

Script it

"Call Claude from a pipeline and parse the result."

claude --bare -p with --output-format json and --json-schema.
